How we measure
Paired tasks
Each task is a real feature request against a starter web app (for example "add a modal dialog" or "make this table responsive"). The same agent and model runs it without MWG (unguided) and with MWG (guided). Nothing else changes.
Pass rate
Every task has deterministic Playwright and static-analysis checks derived from the guide's expectations. Pass rate is checks passed ÷ checks graded, pooled across tasks and suites; a crash or timeout counts as one failed check. Deltas are reported in percentage points (pp).
Why isn't With MWG 100%?
MWG is a steering signal, not a deterministic compiler. Guided runs still miss ~10–20% of checks for three reasons we track openly: model non-determinism (an agent may follow 15 of 16 constraints in a guide and skip one, such as a conditional polyfill), organic skill triggering (prompts never name MWG, so agents must decide when to search and which guide to read), and guide or grader edge cases that nightly runs help us catch and fix.
Accessibility subscore
Pass rate on the subset of checks that test accessibility requirements (focus and inert management, reduced motion and contrast, ARIA roles and live regions, form labels, keyboard operability) across all guides.
Time
Median agent time per task (excluding grader execution) over paired tasks in the same suite. Time and token medians are reported per agent family rather than pooled across families.
Uncached tokens
Total tokens minus cached prompt re-reads (total − cached). Because cached re-reads make up 85–96% of raw totals on Claude Code and Codex CLI, uncached tokens measure the new input, output, and reasoning tokens actually consumed.
Nightly suites
Suites named nightly-<date>-<agent> run on a fixed task set. Headline figures pool the latest 3 nightly suites per agent family: Claude Code, Codex CLI, and Antigravity CLI.
Source
The evaluation harness, task prompts, and graders live in GoogleChrome/modern-web-guidance-src.

How we measure
Paired tasks
Each task is a real feature request against a small web app (for example "add a modal dialog" or "make this table responsive"). The same agent and model runs it unguided (no MWG) and guided (MWG skill installed, so it can search and retrieve guides). Nothing else changes.
Nightly suites
Suites named nightly-<date>-<agent> run on a nightly schedule against a fixed task set. The headline pools the latest 3 nightly suites per agent family: Claude Code, Codex CLI, and Antigravity CLI (antigravity_cli, the Gemini-based CLI that succeeded jetski_cli).
Pass rate
Every task has deterministic grader checks (Playwright and static analysis) derived from the guide's expectations. Pass rate is checks passed ÷ checks graded, pooled across tasks and suites. A run that crashes or times out before grading counts as one failed check. Changes are reported in percentage points (pp).
Accessibility subscore
The pass rate on the subset of checks that test accessibility requirements (focus and inert management, reduced motion and contrast, ARIA roles and live regions, form labels, keyboard operability). Most of these live inside forms, UI component, and CSS guides, not only the accessibility/ guides.
Time
Median agent time per task (agent only, excluding the grader), over tasks that have both an unguided and a guided run in the same suite. "% of tasks faster" compares those pairs one by one. Time and token medians are shown per agent family only; pooling them across families would mix 30-second and 7-minute tasks.
Source
Harness, task prompts, and graders are open source in GoogleChrome/modern-web-guidance-src (harness/ and each guide's targets/).
Uncached tokens
Total tokens minus cached prompt re-reads (total − cached). Raw totals are dominated by cached re-reads on every tool turn (roughly 85–96% for Claude Code and Codex CLI), so uncached tokens measure the new input, output, and reasoning tokens actually consumed. Runs that timed out and reported no token usage are excluded from token medians.

Cross-cutting accessibility subscore
Aggregates the deterministic grader assertions that test accessibility requirements (currently ~110 across 50+ guides: focus & inert management, reduced motion & contrast, ARIA roles & live regions, form labels, keyboard operability)—not just the checks in guides/accessibility/.
Uncached tokens (total − cached)
Raw total token counts are dominated by cached prompt re-reads on each tool turn (roughly 85–96% for Claude Code and Codex CLI; ~20% for Antigravity CLI). Uncached tokens measure the new input, output, and reasoning tokens actually consumed.
Scheduled runs
Suites named nightly-… or weekly-… run automatically on a fixed task set. Everything else is an ad-hoc or test run and is hidden by default.

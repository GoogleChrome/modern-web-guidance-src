How we test & measure
Controlled A/B tasks
Each benchmark task starts with a small starter web app and a synthetic feature prompt (for example, "add search-term highlighting" or "animate this dialog open and closed"). We run the exact same agent, model, and prompt twice: once without MWG and once with MWG installed as a skill. Nothing else changes between the two runs.
Grading & pass rate
After the agent finishes editing code, an automated test script opens the app in a headless browser (Playwright) and inspects the code to check each best-practice requirement. Pass rate is total checks passed divided by total checks run. If an agent crashes or times out before tests can run, that run counts as one failed check. Changes are shown in percentage points (pp). Moving from 25% to 90% is +65 pp.
Why isn't "With MWG" 100%?
Guidance is documentation an AI agent reads rather than a code generator. Guided runs still miss roughly 10–20% of checks for three practical reasons: skipped details (an agent may follow 15 of 16 steps in a guide and overlook one, such as a fallback for older browsers), choosing when to consult a guide (task prompts never mention MWG by name, so the agent must recognize on its own which guide applies), and strict test edge cases that nightly runs help us catch and refine.
Accessibility subscore
Pass rate on accessibility checks across all guides, beyond dedicated accessibility guides. Covers keyboard support, focus and inert handling, prefers-reduced-motion and contrast, ARIA roles and announcements, and form labels.
Completion time
Median wall-clock time the agent spends coding a task, excluding our browser grading step. Because each agent CLI operates differently, we compare median time per agent rather than combining times across different agents.
Token usage (uncached)
Tokens measure how much text the AI model reads and writes. As an agent works across multiple steps, it repeatedly re-sends earlier conversation history from a fast cache (85–96% of raw tokens in some CLIs). We report uncached tokens (total − cached) so you see the newly read guides, code edits, and reasoning each task actually required.
Scheduled nightly runs
Automated benchmark suites (nightly-<date>-<agent>) run against the full task set on a regular schedule. Headline numbers combine the latest nightly run from each agent: Claude Code, Codex CLI, and Antigravity CLI.
Open-source benchmark
All guides, starter apps, task prompts, and browser test scripts are public in GoogleChrome/modern-web-guidance-src.

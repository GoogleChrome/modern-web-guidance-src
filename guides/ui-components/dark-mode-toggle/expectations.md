- The document `<head>` includes `<meta name="color-scheme" content="light dark">` and the root element (`:root` or `html`) declares `color-scheme: light dark` as its base value.
- The root element (`:root` or `html`) uses CSS `:has()` selectors matching `meta[name="color-scheme"]` with `content="dark"` and `content="light"` to set the root `color-scheme` property to `dark` and `light` respectively without relying on JS-applied root classes.
- A synchronous inline `<script>` in `<head>` (without `type="module"`, `defer`, or `async`) placed after `<meta name="color-scheme">` reads `localStorage` and applies any stored scheme override to the `<meta name="color-scheme">` `content` attribute before the page renders.
- Activating the color scheme control to override the scheme sets `<meta name="color-scheme">` `content` to `"light"` or `"dark"`, updates the root element's computed `color-scheme` to match, and persists the override in `localStorage`.
- Reverting or setting the color scheme control back to the system default restores `<meta name="color-scheme">` `content` to `"light dark"` and removes the stored override entry from `localStorage` rather than storing `"light dark"` or pinning the current system scheme.
- When a `"light"` or `"dark"` override is stored in `localStorage` and the OS `prefers-color-scheme` media query changes to match that stored value and then changes back, the override entry remains in `localStorage` and the root element stays pinned to the overridden scheme.
- Updating the stored color scheme entry in `localStorage` and dispatching a `storage` event on `window` updates `<meta name="color-scheme">` `content` to the new stored value (or `"light dark"` when removed).

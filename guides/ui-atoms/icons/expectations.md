- Custom properties `--icon-start` and `--icon-end` are registered using `@property` with `syntax: "*"` and `inherits: false`.
- The guide explains that relative URLs in unregistered custom properties resolve relative to the consuming stylesheet, and recommends root-relative URLs or data URIs by default. It does not recommend registering a token as `<image>` with the URL in `initial-value`, which only works in Firefox. Where relative URLs are unavoidable, it registers the token with a syntax that starts with `<url>` and declares the URL on `:root`.
- CSS Container Style Queries (`@container style(...)`) are used to dynamically detect and render `--icon-start` and `--icon-end` custom properties.
- A compatibility fallback using zero-specificity class hooks (such as `:where(.icon-start)`, `:where(.icon-end)`, and `:where(.icon:empty)`) is provided so CSS-assigned icons render in browsers without Container Style Queries; `content: image-set(linear-gradient(transparent 0 100%), var(--icon-start))` ensures the pseudo-element content becomes `none` when no icon is set.
- The Safari rendering workaround for WebKit #301609 and #320220 applies a zero-duration `@keyframes` animation (e.g., `@keyframes webkit-301609 {}`) to `::before` and `::after` inside the Safari `@supports` condition `((-webkit-nbsp-mode: normal) or (-webkit-touch-callout: none) or (font: -apple-system-body)) and (content-visibility: auto)` so icons render immediately on load.
- The Safari workaround for WebKit #325900 re-registers `--icon-start` with `inherits: true` inside the same Safari `@supports` condition and resets it on descendants inside a layered `@container style(--icon-start)` rule.
- Icons are rendered using CSS `mask` inside the container style query blocks on pseudo-elements (`::before` and `::after`).
- Icons are colored using `currentColor` (via `background-color: currentColor` on the pseudo-element) so they automatically inherit and transition with the parent element's text color.
- Empty `.icon` elements, including icon-only buttons, forward a generic `--icon` property to `--icon-start` (`.icon:empty`).
- Spacing (`margin-inline-start` or `margin-inline-end`) is automatically applied to pseudo-element icons only when the parent element has non-empty content (using `:not(.icon, :empty)` or equivalent selectors).
- Single-color decorative icons are rendered via CSS custom properties (`--icon-start`, `--icon-end`, or `--icon`) rather than inline `<svg>` markup inside buttons, `<img>` tags, or external icon fonts.
- Interactive icon-only controls can apply the `.icon` class and `--icon` property directly to the control, and provide a valid accessible name (such as via `aria-label`).
- Standalone non-interactive empty `.icon` elements use `aria-hidden="true"` when decorative, or `role="img"` with a valid accessible name when informative.
- Sizing of icon pseudo-elements uses relative CSS units (such as `em`, `rem`, or `lh`) rather than hardcoded pixel dimensions.

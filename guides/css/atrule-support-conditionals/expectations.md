- Stylesheets conditionally apply CSS rules or declarations based on at-rule support using the guide's Baseline Widely Available detection hierarchy for the target feature: `@supports at-rule(@<name>)` only when detecting an at-rule whose browser support is narrower than `@supports at-rule()` itself (or when detecting `@supports at-rule()` support via `@supports at-rule(@media)`), and otherwise the matching fallback detection pattern in order of preference (`@supports (<prop>: <val>)` or `@supports selector(...)` when an associated property, value, function, or selector exists; a tautological `@container style(--<prop>: <val>) or (not (style(--<prop>: <val>)))` query for style container queries; a registered `@property` custom property fallback for `@property` when whitespace is a valid fallback (and on a non-root element when using the `:root` space-override pattern); or a JS `CSS*Rule` / `CSSStyleSheet.replaceSync()` check toggling a root class as a last resort when CSS-only detection cannot express the check).
- The at-rule support detection passes only a bare `@<name>` identifier inside any `@supports at-rule(...)` query (without descriptors, preludes, or rule bodies) and does not use invalid or mismatched checks (`@supports (container-type: style)` or `CSS.registerProperty`).
- The at-rule support conditional gates dependent regular CSS declarations or rules in stylesheets rather than wrapping only the detected at-rule itself inside `@supports at-rule(...)` with no other dependent styles or applying visual inline styles directly from JavaScript.

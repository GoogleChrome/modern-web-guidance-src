- Stylesheets declare `text-fit` on the lockup heading using `per-line-all` (not `per-line`), either `grow` or `shrink` (not both), and an explicit `<percentage>` guardrail limit alongside a base `font-size`.
- The lockup container has a definite inline size (not `fit-content` or `max-content`), and the lockup heading sets a tight `line-height` of `1` or less.
- Forced line `<span>` elements inside a lockup are styled with `display: block` and `white-space: nowrap` so each forced line stays on a single line at its base font size.
- Each lockup either spaces all-forced line blocks using flex or grid `gap` with `text-box: trim-both cap alphabetic` on each line block, or styles free-wrapping lines with `text-wrap: balance` or `text-wrap: pretty` without `text-box` trimming.
- An `@supports not (text-fit: grow)` (or `@supports not (text-fit: ...)`) fallback rule sets `width: fit-content` on forced line elements and scales their `font-size` with `min()` using a CSS custom property capped at the maximum percentage.
- When `CSS.supports(...)` indicates `text-fit` is unsupported, a `ResizeObserver` fallback script resets the scale custom property on forced lines, batch-reads all container and line widths (such as `clientWidth` and `offsetWidth` or `getBoundingClientRect().width`) before writing the new custom property values, and updates each line's scale factor on resize.

- Server-rendered HTML uses processing instruction syntax (`<?target ...>`) with valid target names (starting with an ASCII letter or underscore, and not `xml` or `xml-stylesheet`) to mark positions or ranges in the markup without adding extra wrapper elements.
- All attributes attached to processing instructions in the HTML markup use explicit `name="value"` or `name='value'` quoted syntax, with any `<`, `>`, `&`, or quote characters inside attribute values escaped as XML entities (`&lt;`, `&gt;`, `&amp;`, `&quot;`, `&apos;`).
- Client-side JavaScript locates processing instruction markers in the DOM using `document.createTreeWalker` or `document.createNodeIterator` with `NodeFilter.SHOW_PROCESSING_INSTRUCTION` rather than CSS selector queries.
- Client-side JavaScript reads or updates metadata on processing instruction nodes using `.target` and the `ProcessingInstruction` attribute methods (`getAttribute`, `setAttribute`, `hasAttribute`, `removeAttribute`, `toggleAttribute`, `getAttributeNames`, or `hasAttributes`).
- Range updates replace or manipulate the DOM nodes between a start processing instruction and its matching end processing instruction while keeping both boundary processing instruction nodes in the DOM for subsequent updates.
- A fallback guarded by feature detection (such as `Object.hasOwn(ProcessingInstruction.prototype, 'getAttribute')`) handles browsers that parse `<?...>` as `Comment` nodes starting with `?` and lack native `ProcessingInstruction` attribute methods, so marker discovery and attribute access work across browsers.
